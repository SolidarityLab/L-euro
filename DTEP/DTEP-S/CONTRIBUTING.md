# Contributing to DTEP-S

Thank you for your interest in DTEP-S. This is an open protocol specification project — contributions from implementers, domain experts, and researchers are welcome and necessary for the protocol to mature.

## What we are looking for

The project is in specification phase (v0.1-draft). The most valuable contributions at this stage are:

**Protocol review** — reading the specifications and identifying ambiguities, gaps, or inconsistencies. If something is unclear to you as a potential implementer, it is a defect in the specification.

**Implementation feedback** — if you are implementing or piloting any component of the protocol, your practical findings are the most valuable input we can receive. What works, what does not, what the specification fails to anticipate.

**Domain expertise** — the protocol is designed for humanitarian and social protection contexts. If you work in these domains — as an administrator, NGO practitioner, or policy specialist — your perspective on the operational realities is essential.

**Standards alignment** — if you identify conflicts or opportunities for better alignment with W3C VC 2.0, eIDAS 2.0 ARF, ISO/IEC 18013-5, or other relevant standards, please raise them.

**Security analysis** — the threat model is in early draft. Identified attack vectors, privacy risks, or cryptographic weaknesses are welcome.

## How to contribute

**Issues** are the primary contribution mechanism at this stage. Open an issue for:

- Specification ambiguity or gap
- Proposed extension or modification
- Implementation finding
- Security or privacy concern
- Standards alignment question

Please reference the specific specification file and section in your issue.

**Pull requests** are welcome for:

- Corrections to existing specification text
- Addition of examples
- Documentation improvements
- Schema corrections

For substantive protocol changes — new fields, modified flows, changed validation rules — open an issue first. Protocol changes require discussion before specification update.

## Specification versioning

The current version is v0.1-draft. At this stage the specification is unstable — breaking changes are expected. Once v0.2 is published, a stability policy will be defined.

All open issues from each specification file are tracked in the repository issues. If you are working on something listed as an open issue, comment on the issue to coordinate.

## Scope

DTEP-S is the Social Layer of the DTEP protocol family. Contributions scoped to the fiscal layer (DTEP-F) or to the broader DTEP architecture are out of scope for this repository.

The protocol is domain-neutral by design. Contributions that introduce domain-specific constraints into the base schema are out of scope — domain extensions belong in Issuer configuration, not in the protocol.
